# ADR-0003: 正確な日時より「ざっくりした未来」を選ばせる

- Status: Accepted
- Date: 2026-08-18

## Context

正確な日時指定はリマインダーとしては便利だが、Re:Me の偶然性を弱くする。一方、完全ランダムだけでは判断用途で「遅い」が起きる。

## Decision

ユーザーは厳密日時ではなく配送レンジを選ぶ。システムはレンジ内で実際の `scheduledAt` を送信時に一度だけ決定する。

## Consequences

- 判断用途と振り返り用途を同じ UX で扱える
- 「いつ頃」は分かるが exact な日時は分からない
- 配送レンジの調整がプロダクト体験に直結する
- 「未来に任せる」のアルゴリズムは重要な検証ポイントになる
